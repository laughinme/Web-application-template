# Как мы пишем тексты

Всё, что будут читать люди (README, документы, ADR, STATUS, описания PR и тела коммитов, тексты
интерфейса, презентации), агент пишет со скиллом `humanizer`: загружает его, пишет черновик,
сверяет с его списком признаков и исправляет. Скилл собран по
[Signs of AI writing](https://en.wikipedia.org/wiki/Wikipedia:Signs_of_AI_writing) из Википедии.

Самое частое, что он убирает:

- противопоставления ради веса: «это не просто X, а Y»;
- финальные фразы-выводы, которые повторяют абзац;
- тройки там, где пунктов на самом деле два или четыре;
- тире вместо выбора связки (точка, запятая, двоеточие);
- жирные ярлыки у каждого пункта списка и эмодзи в заголовках;
- раздувание значимости: «ключевой», «критически важный», «играет важную роль»;
- остатки чата: «надеюсь, это поможет», «давайте разберём».

Правила для технических текстов:

- Начинать с сути. Читатель README хочет запустить проект, читатель ADR хочет решение.
- Факты, команды и пути, а не оценки. «Тест падает, если модель поменяли без миграции» вместо
  «надёжная проверка миграций».
- Ничего не выдумывать: числа, имена, версии только из кода, команд и источников.
- Короткие и длинные предложения вперемешку. Таблица там, где сравнение, проза там, где объяснение.
- Интерфейс: глаголы на кнопках («Сохранить», «Заблокировать»), ошибки говорят, что делать
  («Проверьте email; пароль — не короче 8 символов»), а не что сломалось внутри.
