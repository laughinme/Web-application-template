# Скиллы и инструменты агента

Что установлено у владельца и когда это использовать. Пользовательские скиллы лежат в
`~/.claude/skills/`, скиллы проекта в `.claude/skills/` репозитория.

| Задача | Чем | Заметки |
| --- | --- | --- |
| Документация библиотеки, API, версии | Context7 MCP | всегда до кода, который зависит от сторонней библиотеки; не по памяти |
| Любой текст для людей | скилл `humanizer` | [writing.md](writing.md) |
| Любая визуальная работа | скилл `design-studio` | маршрутизатор: Impeccable, frontend-design, cinematic-scroll, GSAP, Refero, Mobbin; [design.md](design.md) |
| Деплой «на сервер», «на сару», на prooood.ru | скилл `home-server-deploy` | [deploy.md](deploy.md) |
| Новая фича в этом шаблоне | скилл проекта `add-feature` | обёртка над [new-feature.md](../backend/new-feature.md) |
| Ревью изменений | `/code-review` | перед PR или после большого рефакторинга |
| Проверка экранов | Playwright (`npm run test:e2e`, скриншоты) | 1440 и 390 px |
| Библиотеки анимации | скиллы `gsap-*`, `vercel-react-view-transitions` | через `design-studio` |
| Широкий поиск или ресёрч | субагенты (`Explore`, `general-purpose`) | чтобы не забивать основной контекст |

Когда что-то из этого должно срабатывать всегда, правило записано в глобальном
`~/.claude/CLAUDE.md` владельца: Context7, design-studio, humanizer, home-server-deploy, этот шаблон
как основа новых проектов. Проекты на основе шаблона повторяют это в своём `CLAUDE.md`.

## Свой скилл

Повторяемая многошаговая процедура проекта (релиз, новая фича, заливка данных) оформляется скиллом
в `.claude/skills/<имя>/SKILL.md`, а не строкой в `AGENTS.md`: скилл загружается только когда нужен.
Во frontmatter `name` и `description`, в описании сначала, когда его применять. Тело до 500 строк,
подробности в соседних файлах. Процедура с побочными эффектами (деплой, удаление) получает
`disable-model-invocation: true`, чтобы агент не запустил её сам. Пример: `.claude/skills/add-feature`.
