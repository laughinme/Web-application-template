# Контекстные файлы и документация проекта

Как мы раскладываем знания о проекте, чтобы их одинаково легко читали агенты (Claude Code, Codex,
Cursor) и люди. Правила выведены из наших проектов (avito-helpus, RoboSim, Островок, hack_nn) и
опираются на открытые источники:

- [agents.md](https://agents.md/): открытый формат `AGENTS.md`, его читают Codex, Cursor, Copilot,
  Gemini CLI и другие; ближайший к файлу `AGENTS.md` главнее;
- [документация Claude Code о памяти](https://code.claude.com/docs/en/memory): `CLAUDE.md`, импорт
  `@файл`, правила в `.claude/rules/` с привязкой к путям, рекомендация держать файл короче 200 строк;
- [best practices Claude Code](https://code.claude.com/docs/en/best-practices): писать только то,
  что агент не найдёт сам; длинные процедуры выносить в скиллы; жёсткие правила проверять хуками и
  линтерами, а не словом IMPORTANT.

## Раскладка

```text
AGENTS.md            канонический бриф для любого агента (до ~150 строк)
CLAUDE.md            @AGENTS.md и только то, что касается Claude Code
README.md            для людей: что это, как запустить, где что лежит
PRODUCT.md           продукт: аудитория, задачи, принципы (если есть UI)
DESIGN.md            дизайн-система по спецификации Google DESIGN.md (если есть UI)
backend/AGENTS.md    локальные правила части; рядом CLAUDE.md с одной строкой @AGENTS.md
frontend/AGENTS.md   то же для фронтенда
docs/
  README.md          оглавление: какой файл когда читать
  STATUS.md          где мы сейчас: готово, в работе, дальше, риски (до ~80 строк)
  DECISIONS.md       журнал решений D-NNN и открытые вопросы Q-NNN
  backend/, frontend/, guides/   тематические документы, один предмет на файл
  case/              материалы заказчика или организаторов, только чтение (если есть)
  archive/           устаревшее, только для справки
design/              референсы, раскадровка, decisions.md дизайна
.claude/skills/      скиллы проекта: повторяемые процедуры (например add-feature)
```

Claude Code читает `AGENTS.md` сам, только если в проекте нет `CLAUDE.md`. Поэтому `CLAUDE.md`
всегда есть и начинается с `@AGENTS.md`: один источник правды для всех инструментов, без
расхождений. Вложенный `CLAUDE.md` Claude Code подгружает, когда начинает работать с файлами этой
папки.

## Что писать в AGENTS.md

1. Проект одной-двумя фразами, язык общения.
2. Ритуал сессии: что прочитать в начале (`docs/STATUS.md`, `docs/DECISIONS.md`, документ своей
   части), что обновить в конце.
3. Карта: таблица «где → что» со ссылками.
4. Жёсткие правила, которые нельзя вывести из кода, и порядок источников правды при конфликте.
5. Команды: запуск, проверки, один тест, миграция.
6. Таблица «что произошло → куда записать».

Не писать: то, что видно из кода (список файлов целиком, описание каждой функции), пересказ
документов (ставим ссылку), историю изменений (она в git). Правило, которое агент нарушил дважды,
сначала пробуем превратить в проверку (линтер, import-linter, steiger, тест, хук) и только потом
в строку `AGENTS.md`.

## Куда записывать

| Что произошло | Куда |
| --- | --- |
| Приняли решение (стек, подход, граница MVP) | `docs/DECISIONS.md`: D-NNN, дата, решение, почему, что отвергли |
| Появился открытый вопрос | `docs/DECISIONS.md`, раздел «Открытые вопросы» (Q-NNN) |
| Закончили заметный кусок работы | переписать `docs/STATUS.md` целиком, коротко |
| Поменялся API или модель данных | код, `make openapi`, документ части |
| Узнали ловушку окружения или данных | документ части или `AGENTS.md`, если касается всех |
| Изменилась дизайн-система | `DESIGN.md`, `design/decisions.md` |

`STATUS.md` переписывается, а не дописывается. Журналы сессий не ведём: файл на 1500 строк никто не
читает, а история уже есть в git. Отменённое решение не удаляем, а помечаем «заменено D-NNN».

## Документы в docs/

- Один предмет на файл, до ~300 строк. Вырос, значит пора делить.
- В начале файла одна-две фразы, о чём он, и ссылки на соседей.
- Ссылки на код относительные: `[core/errors.py](../../backend/app/core/errors.py)`.
- Схемы в mermaid, примеры кода короткие и настоящие (из репозитория, а не придуманные).
- Язык документации тот же, что у команды (обычно русский). Код, идентификаторы и коммиты на
  английском.
- Тексты проходят через скилл `humanizer`: [writing.md](writing.md).

Шаблоны файлов для нового проекта: [docs/templates/](../templates/).
