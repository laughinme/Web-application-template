# Журнал решений

Каждое решение: номер, дата, что решили, почему, что отвергли. Новые записи в конец. Отменённое
решение не удаляем, а помечаем «заменено D-NNN». Старая версия шаблона лежит в ветке `legacy`.

<a id="d-001"></a>

## D-001. Бэкенд по слоям, в каждом слое зоны (15.11.2026)

`api`, `service`, `domain`, `db`, `infra`, `ports`, `core`; внутри `api/v1`, `service` и `domain`
папка на каждую зону (`auth`, `users`, `moderation`, …). Границы проверяет import-linter.
Почему: так устроены Cosmic Python и официальный full-stack шаблон FastAPI, так привычно команде и
так же устроены RoboSim и Островок. Одно правило зависимостей легко проверять автоматически.
Отвергли: модули по фичам (`app/modules/<feature>/{router,service,domain,models}`), как у Netflix
Dispatch и fastapi-best-practices. Вариант был собран 15.11 и отклонён владельцем: на текущем размере
папка-фича с плоскими файлами читается хуже, чем слои. Вернуться к нему стоит, когда зон станет 8–10
или появится вторая команда: зоны уже названы одинаково во всех слоях, переезд механический.

<a id="d-002"></a>

## D-002. Одна транзакция на запрос, сервисы только flush (27.10.2026)

Коммитит владелец UoW: `UowDep` (`Depends(scope="function")`, коммит до отправки ответа), воркер,
CLI. Почему: сервисы можно сочетать, а упавший коммит даёт 500, а не 200 без данных.
Отвергли: коммит внутри сервисов (полузаписанные сценарии), `scope="request"` (коммит после ответа).

<a id="d-003"></a>

## D-003. Абстракции только для внешних систем (15.11.2026)

`app/ports/` описывает Protocol для хранилища и уведомлений, `infra` их реализует, сервисы не
импортируют `infra`. Репозитории остаются конкретными классами.
Почему: порт нужен там, где есть внешняя система или больше одной реализации (S3 и фейк, лог и
Telegram). Абстрактный репозиторий удваивает каждую сигнатуру, а его настоящую проверку всё равно
дают интеграционные тесты на Postgres. Так же советует Cosmic Python (гл. 2).
Отвергли: `AbstractRepository`/`AbstractUnitOfWork` на ABC для всего.

<a id="d-004"></a>

## D-004. Outbox доставляется вне транзакции, с арендой (15.11.2026)

Воркер забирает пачку событий короткой транзакцией и сдвигает `available_at` на `OUTBOX_LEASE_SEC`,
вызывает обработчики без открытой транзакции, результат пишет второй транзакцией.
Почему: раньше вызовы Telegram и S3 шли внутри транзакции с блокировками `FOR UPDATE`; при таймаутах
транзакция могла висеть минутами. Нашло независимое ревью архитектуры.
Отвергли: брокер (Redis Streams, RabbitMQ): для монолита лишняя инфраструктура, Postgres справляется.

<a id="d-005"></a>

## D-005. Одна глобальная роль на пользователя (27.10.2026)

Колонка `role` (enum) и права в коде (`ROLE_PERMISSIONS`). Эндпоинты проверяют права, количество
ролей знает только `CurrentUser.can()`.
Почему: в старом шаблоне роли были лестницей (`admin` включал `member`), а таблицы ролей, кэш в Redis
и `expand_roles` ничего не давали.
Как расширять: независимые глобальные роли через `ARRAY` enum'а и `any()` в `can()`; роли внутри
организаций через отдельную таблицу членства, глобальная роль при этом остаётся.

<a id="d-006"></a>

## D-006. Фронтенд: FSD, типы из OpenAPI (15.11.2026)

Маршруты Next в корневом `app/`, код в `src/` по слоям FSD с именами `_app` и `_pages` (официальный
гайд FSD для Next.js). DTO генерирует openapi-typescript, границы проверяет steiger.
Почему: ручные DTO расходились с API, `shared` импортировал `entities`, демо-дашборд shadcn
выглядел как функциональность, которой нет.
Отвергли: `src/views` вместо `_pages` (steiger не знает такой слой), orval/hey-api (генерация клиента
целиком: для текущего размера хватает типов и тонкого axios).

<a id="d-007"></a>

## D-007. Схема ошибки и ErrorCode в OpenAPI (15.11.2026)

Все эндпоинты `/api/v1` описывают ответы `4XX` и `5XX` моделью `Problem` с полем `error_code: ErrorCode`.
Почему: фронтенд получает коды ошибок как union-тип, опечатка в коде ошибки ловится компилятором.

<a id="d-008"></a>

## D-008. RustFS вместо MinIO локально (27.10.2026)

Образы MinIO перестали публиковаться в Docker Hub. RustFS совместим с S3 и распространяется под Apache-2.0.
В проде подходит любой S3, меняются только `STORAGE_*`.
